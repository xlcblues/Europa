# Europa 小游戏设计文档

> 项目：Europa（木卫二） Windows 桌面端小游戏合集  
> 版本：v0.5 · M0 设计、M1 工程、M2 环带贪吃蛇、M3 冰原跃迁、M4 星盘五子棋与 M5 设置/音频/记录  
> 状态：M2 环带贪吃蛇、M3 冰原跃迁、M4 星盘五子棋与 M5 设置/音频/记录均已实现并验收  
> 日期：2026-11-09

## 1. 合集共同设计

### 1.1 三个小游戏

| 游戏 | 类型 | 一句定位 | 单局时长 |
| --- | --- | --- | --- |
| 冰原跃迁 | 横版平台跳跃 | 操控探测器穿越冰原，收集碎片并抵达信标 | 3 个关卡，8–15 分钟 |
| 环带贪吃蛇 | 经典街机 / 无尽模式 | 在环形网格中不断生长，追求更高分 | 1–10 分钟 |
| 星盘五子棋 | 回合策略 | 在星盘上与好友或 AI 连成五子 | 3–15 分钟 |

三款游戏均采用原创美术与规则表达。类型上可参考经典玩法，但不使用任天堂角色、名称、音效、关卡或任何第三方受版权保护的素材。

### 1.2 统一操作约定

| 操作 | 键位 |
| --- | --- |
| 移动 | `A / D` 或 `← / →` |
| 上下 / 辅助 | `W / S` 或 `↑ / ↓`，按具体游戏定义 |
| 主要动作 | `Space` |
| 暂停 / 返回 | `Esc` |
| 确认 | `Enter` |
| 重开 | 仅在暂停层或结果层可使用 `R`，避免误触 |
| 提示 / 关闭 | `Esc` 关闭弹窗，不直接退出应用 |

### 1.3 通用生命周期

```text
Ready → Playing ↔ Paused → Result
   ↘ GameOver / Victory ────↗
```

- **Ready**：游戏说明与“开始”入口，允许选择难度或模式。
- **Playing**：输入、音频、计时与规则推进。
- **Paused**：冻结逻辑；显示继续、重开、返回游戏库和设置。
- **Result**：保留最后一帧，显示成绩、胜负、统计和主要操作。
- 窗口失焦、系统最小化与切到设置页时自动暂停。
- 应用关闭前若存在可恢复状态，执行一次简短保存并显示保存结果。

### 1.4 统一界面

- 游戏舞台始终使用深色 `--art-stage`，保证沉浸感。
- 顶栏提供返回游戏库、当前游戏名、状态胶囊、音效和设置。
- HUD 不遮挡可玩区域；关键数值使用等宽数字。
- 暂停与结果使用 480px 玻璃弹窗，主操作为“继续/再来一局”。
- 分数刷新最高分时使用暖金，但只在数字和星点小面积出现。
- 每局结束生成 `GameResult`，统一写入统计与历史记录。

### 1.5 统一存档原则

- 设置与统计数据跨游戏共享。
- 游戏内逐帧状态不持续写盘。
- 平台跳跃保存到关卡内检查点；贪吃蛇仅保存最高分；五子棋首版保存对局结果与统计。
- 存储失败不阻断游戏，但必须显示持久提示，并提供重试或导出备份。

## 2. 冰原跃迁

### 2.1 游戏定位

- **英文代号**：`platformer`
- **类型**：单人横版平台跳跃
- **主题**：木卫二冰壳探测器穿越裂隙，寻找轨道信标
- **核心体验**：稳定、轻盈的跳跃手感；短关卡内完成收集与路线选择
- **主角**：原创角色 **E-17 冰面探测单元**，小型青白发光探测器，不使用人类或马里奥式角色造型
- **MVP 关卡数**：3 个手工关卡

### 2.2 核心循环

```text
观察地形 → 移动/跳跃 → 收集冰晶 → 避开裂隙与哨兵
→ 激活检查点 → 抵达轨道信标 → 结算关卡 → 进入下一关
```

每关 60–180 秒，关卡内部有一次检查点。玩家在有限的 3 条生命中完成全部关卡，追求更高总分和全收集。

### 2.3 操作

| 行为 | 键位 | 规则 |
| --- | --- | --- |
| 左右移动 | `A / D` 或 `← / →` | 有加减速，不是瞬时满速 |
| 跳跃 | `Space / W / ↑` | 支持可变跳跃高度；按住可跳得更高 |
| 下穿平台 | `S / ↓` | 仅对单向平台有效 |
| 暂停 | `Esc` | 冻结物理、计时与音频 |
| 继续 | `Enter / Space` | 暂停层主操作 |
| 重开本关 | 暂停层 `R` 或按钮 | 从最近检查点开始；会消耗一次重置确认 |

### 2.4 移动与跳跃手感

以下数值为首轮调参基线，最终以试玩为准：

| 参数 | 建议值 |
| --- | --- |
| 逻辑帧率 | 固定 60Hz |
| 最大水平速度 | `260 px/s` |
| 水平加速度 | `1200 px/s²` |
| 水平减速度 | `1600 px/s²` |
| 起跳速度 | `-560 px/s` |
| 重力 | `1600 px/s²` |
| 最大下落速度 | `900 px/s` |
| 可变跳跃 | 松开跳跃时竖直速度截断 45% |
| 土狼时间 | `100ms` |
| 跳跃缓冲 | `120ms` |
| 受击无敌 | `1.5s` |
| 摄像机平滑 | 位置插值，不用弹簧过度晃动 |

手感原则：

- 先保证可预期，再增加“弹性”。
- 角色贴地、起跳、落地的反馈必须在 1–2 帧内出现。
- 不使用随机惯性或自动吸附，除非有明确的辅助模式开关。
- 高低帧率下逻辑保持一致，渲染只做插值。

### 2.5 关卡与规则

#### 基础规则

- 玩家初始 3 条生命，生命跨关卡保留。
- 收集冰晶、踩踏哨兵、到达信标、全收集可获得分数。
- 坠入裂隙或与哨兵侧面接触会损失 1 条生命，并从最近检查点重生。
- 生命归零时本局结束，提交当前总分。
- 检查点会保存关卡内位置、当前分数、生命和收集状态，但不保存正在进行的瞬时物理状态。

#### 关卡 1：初醒冰原

- 目标：教学移动、跳跃和收集。
- 时长目标：60–90 秒。
- 元素：平地、低台阶、2 个单向平台、3 组冰晶、1 个哨兵、1 个检查点、终点信标。
- 设计要求：第一屏内不出现即死陷阱；死路不超过一次。

#### 关卡 2：裂隙回廊

- 目标：掌握跳跃间距与移动平台。
- 时长目标：90–150 秒。
- 元素：裂隙、移动平台、交错高低差、2 个哨兵、4 组冰晶、1 个检查点。
- 设计要求：关键跳跃有 2 种可行路线，至少一种不要求精确踩点。

#### 关卡 3：潮汐之眼

- 目标：组合能力与风险收益。
- 时长目标：120–180 秒。
- 元素：上下层路线、窄平台、单向平台、3 个哨兵、5 组冰晶、隐藏收集区、2 个检查点、终点。
- 设计要求：全收集路线比安全路线多 20–30 秒，但只提供分数收益，不阻断通关。

#### 敌人与危险

- **巡游哨兵**：在平台上往返移动；从上方踩踏可关闭，侧面接触损失生命。
- **裂隙**：连续的深色缺口，掉入即损失生命。
- **冷雾区（扩展）**：不进入 MVP，可降低能见度但不能只靠颜色警告。

### 2.6 计分规则

| 事件 | 分数 |
| --- | --- |
| 收集 1 个冰晶 | `100` |
| 关闭 1 个哨兵 | `250` |
| 首次激活检查点 | `100` |
| 本关全收集 | `750` |
| 本关零死亡 | `1000` |
| 到达关卡信标 | `1000` |
| 最终通关额外奖励 | `2000` |

- 分数在一整轮游戏中累加，游戏结束时提交。
- 本局已获得的分数不会因重试被扣回；每个收集物在同一关卡内的首次收集才计分，重试后再次触发不重复加分。
- 最高分记录保存总评分；单关最佳可扩展为独立统计，不进入 MVP。
- 结算显示：总分、各关得分、冰晶数量、死亡次数、最高分是否刷新。

### 2.7 开始、暂停与结束流程

1. 从游戏库进入 `Ready` 页面，显示操作说明、最佳分与开始按钮。
2. 点击开始后进入关卡 1，短暂显示关卡名与目标，约 1.2 秒后开放输入。
3. `Esc` 或窗口失焦后进入 `Paused`，冻结物理、计时与音频。
4. 生命归零显示 `GameOver`；完成关卡 3 显示 `Victory`。
5. 结果页提供“再来一局”和“返回游戏库”；若本局未结束，则提供“继续游戏”或“放弃本局”。

### 2.8 界面布局

```text
┌─────────────────────────────────────────────────────────┐
│ 返回游戏库 | 冰原跃迁 | 运行中 | 音效 | 设置              │
├─────────────────────────────────────────────────────────┤
│ HUD：● ● ●生命   冰晶 12/18   分数 4,200   关卡 02         │
│                                                         │
│          16:9 平台跳跃画面（Canvas）                      │
│                                                         │
│             远景视差 → 中景地形 → 角色/交互物              │
└─────────────────────────────────────────────────────────┘
```

- 背景最多三层视差。远景只做氛围，不添加高频粒子干扰。
- 角色始终清晰，可在深色背景上保持 1px 外轮廓或局部高光。
- 死亡、检查点、关卡完成使用图形与文字反馈，不只改变屏幕颜色。
- 暂停时在画面中央显示玻璃弹窗；最后一帧保留并压暗。

### 2.9 存档与数据

- 保存槽：`platformer_main`
- 存档字段：`levelId / checkpointId / score / lives / collectibles / updatedAt`
- 触发：到达检查点、完成关卡、从暂停层退出、窗口关闭且处于可恢复状态。
- 恢复后从检查点位置出现，已收集物保持收集状态，HUD 显示“已恢复至检查点”。
- 检查点保存不改变玩家在本局中已经获得的分数。

### 2.10 可访问性与辅助

- 提供“宽松跳跃”设置：扩大土狼时间与跳跃缓冲，不改变分数倍率。
- 所有即死危险必须有图形预警；不可只依赖红/青颜色差异。
- 可通过字幕/图标显示跳跃、检查点、生命损失等关键事件。
- 减少动态时关闭视差、镜头震动与大范围背景动画。
- 后续支持按键重映射与手柄。

### 2.11 扩展规划

- 新增 2–3 个主题世界与 10+ 关卡；
- 速度挑战 / 全收集挑战；
- 幽灵回放与个人最佳路线；
- 关卡编辑器与创意工坊式本地分享（不联网）；
- 手柄与按键重映射；
- 成就与隐藏区域。

### 2.12 验收标准

- [x] 三个关卡可从开始到结算完整游玩。
- [x] 土狼时间、跳跃缓冲、可变跳跃在 60/120/144Hz 下行为一致。
- [x] 角色不会穿墙或卡入单向平台。
- [x] 检查点保存和恢复位置正确，收集状态不重复。
- [x] 生命、分数、最高分和结算只提交一次。
- [x] 暂停、失焦、恢复不会改变物理状态。
- [x] 全流程键盘可玩，关键事件有可读反馈。

> 验收状态（2026-11-08）：以上 7 项均已由前端引擎/组件测试、Rust 事务测试与固定步长仿真覆盖。检查点恢复、失焦自动暂停、未完成卸载仅存档不结算、幂等结算均已有自动化验证。

## 3. 环带贪吃蛇

### 3.1 游戏定位

- **英文代号**：`snake`
- **类型**：单人街机 / 无尽模式
- **主题**：探测器沿着木卫二冰环轨道延伸，吞噬能量节点
- **核心体验**：短决策、快速反馈、持续加速、追逐最高分
- **MVP 模式**：20×20 网格，经典实墙规则

### 3.2 核心循环

```text
观察食物 → 选择安全方向 → 吃到食物 → 蛇身增长 → 分数增加
→ 每 5 个食物提速 → 避免撞墙与自身 → 直到失败或填满棋盘
```

### 3.3 操作

| 行为 | 键位 | 规则 |
| --- | --- | --- |
| 转向 | `W / A / S / D` 或方向键 | 进入长度 2 的输入队列 |
| 暂停 / 继续 | `Space` 或 `Esc` | 冻结 tick；从当前朝向继续 |
| 开始 | `Enter` 或开始按钮 | 从 Ready 进入 Playing |
| 重开 | 结果页按钮或暂停层 `R` | 清空本局，重新生成 |
| 返回 | 暂停层按钮 | 本局结束，不提交分数 |

输入规则：

- 禁止直接反向：当前向右时不能立即向左。
- 若短时间内连续输入两个合法方向，按队列顺序执行，避免漏转。
- 与当前方向相同的输入不增加队列。
- 非法方向直接忽略，并播放轻微无声反馈或 HUD 提示。

### 3.4 棋盘与节奏

| 参数 | 规则 |
| --- | --- |
| 棋盘 | `20 × 20` 格 |
| 初始蛇长 | 4 格 |
| 初始位置 | 棋盘中心附近，朝右 |
| 初始 tick | `130ms / 格` |
| 提速条件 | 每吃到 5 个食物，tick 减少 `8ms` |
| 最快 tick | `65ms / 格` |
| 食物生成 | 在未被蛇身占用的格子中随机生成 |
| 特殊食物 | MVP 不加入；扩展阶段可加入限时冰核 |
| 墙体 | 实墙，撞墙结束 |
| 自撞 | 撞到自身任意格结束 |
| 空格耗尽 | 填满棋盘判定胜利，提交最高分与胜利记录 |

渲染与逻辑：

- tick 驱动规则，`requestAnimationFrame` 只负责插值绘制。
- 蛇头在相邻 tick 间平滑移动，但碰撞以逻辑格为准。
- 食物、蛇头、蛇身和危险边界的形状必须可区分。
- 每 5 个食物的速度变化附一行 HUD 提示，不改变棋盘大小。

### 3.5 计分与成长

| 事件 | 分数 |
| --- | --- |
| 吃到 1 个食物 | `+10` |
| 填满棋盘 | `+500` 奖励 |
| 每局结束 | 提交总分与蛇长 |

- 不设置倒计时或分数倍率，保证经典规则清晰。
- 最高分只增不减；同分时以更长蛇身与更短用时作为次级展示信息。
- 平均速度、总长度、游玩时长写入统计；食物数量不单独计分。
- 若扩展特殊食物，基础分不得依赖随机运气过高；需在玩法评审后加入。

### 3.6 开始、暂停与结束流程

1. Ready 页展示最高分、操作说明和开始按钮。
2. 点击后显示 1 秒“准备”，蛇头在中心，不立即移动。
3. Playing 中每 tick 移动一次；Space/Esc 进入 Paused。
4. 撞墙或自撞进入 GameOver；填满棋盘进入 Victory。
5. 结果页显示本局分数、蛇长、最高分、速度级别与用时。
6. “再来一局”生成新食物与新初始蛇；“返回游戏库”提交剩余统计。

### 3.7 界面布局

```text
┌─────────────────────────────────────────────────────────┐
│ 返回游戏库 | 环带贪吃蛇 | 运行中 | 音效 | 设置            │
├─────────────────────────────────────────────────────────┤
│ 最高分 1,280 | 本局 240 | 长度 22 | 速度 04 | 暂停        │
│                                                         │
│                 20×20 正方形棋盘（Canvas）                │
│                                                         │
│             网格 / 食物 / 蛇头 / 蛇身 / 尾部高光           │
└─────────────────────────────────────────────────────────┘
```

- 棋盘保持正方形，最大边长约 680px；窗口缩小时优先保留棋盘完整。
- 蛇身由连续圆角单元和微弱连接线构成，头部有方向标识。
- 食物使用暖金星点，符合品牌“星点”语言；不得仅凭颜色识别。
- 墙体边缘使用低对比边框，不画成粗红色警告条。
- 暂停/结束层与合集通用弹窗一致。

### 3.8 数据与存档

- 最高分：`game_stats.best_score`
- 统计：`games_played / total_play_ms / last_played_at`
- 不保存进行中的蛇局；关闭后重新开始。
- 结束提交需幂等：同一会话 ID 只写入一次。
- P1 扩展可保存“每日挑战种子”与本地最佳回放，不写入首版 MVP。

### 3.9 可访问性与辅助

- 支持方向键与 WASD，二者可同时映射。
- 可通过“颜色增强”设置增加蛇头/食物形状差异。
- 暂停界面显示当前长度、分数和速度，方便离开后继续。
- 提供“缓速模式”作为练习开关，不计入标准最高分；排行榜类内容不在 MVP。
- 减少动态时缩短插值时间，但逻辑 tick 不变。

### 3.10 扩展规划

- 环形穿墙模式；
- 障碍物、传送门、限时冰核；
- 每日固定种子挑战；
- 本地幽灵轨迹与个人最佳回放；
- 键盘宏禁用模式与公平计分。

### 3.11 验收标准

- [x] 不可直接 180° 反向，快速输入不丢失合法转向。
- [x] 食物不会生成在蛇身格。
- [x] 每 5 个食物提速一次，达到下限后不再加速。
- [x] 撞墙、自撞、填满棋盘均判定正确。
- [x] 暂停不推进 tick，恢复后方向与速度正确。
- [x] 最高分和局数只提交一次，重启应用后仍存在。
- [x] 棋盘在 1040×700 窗口内完整显示，不出现裁切。

## 4. 星盘五子棋

### 4.1 游戏定位

- **英文代号**：`gomoku`
- **类型**：回合制策略 / 本地双人 / 人机对战
- **主题**：在木卫二星盘上落下黑白信标，连成五子
- **核心体验**：清晰的落子反馈、快速理解胜负线、AI 三档难度
- **MVP 模式**：15×15 自由规则五子棋，无禁手

### 4.2 核心规则

- 棋盘 15×15；黑棋先手，双方轮流落子。
- 横向、纵向或两条对角线形成连续 5 子或以上即获胜。
- 本 MVP 允许超过五子的连续棋形，不采用连珠禁手。
- 棋盘填满且无人获胜时判平局。
- 不允许覆盖已有棋子、跳过回合或在 AI 思考中抢先落子。
- 黑棋与白棋使用相同几何棋子造型，以实心/空心和形状标识区分，不仅依赖颜色。

### 4.3 模式

| 模式 | 说明 |
| --- | --- |
| 本地双人 | 两名玩家在同一台电脑交替落子 |
| 人机对战 | 玩家执黑先手，AI 执白；MVP 固定该先后手 |
| 难度 | 入门、进阶、大师三档 |

扩展阶段允许玩家选择执白、AI 先手、棋盘尺寸 13×13 / 19×19、连珠禁手规则。

### 4.4 操作

| 行为 | 鼠标 | 键盘 |
| --- | --- | --- |
| 选择落点 | 点击交叉点 | 方向键移动棋盘焦点 |
| 落子 | 左键点击 | `Enter / Space` |
| 暂停 | 顶栏按钮 / `Esc` | 同左 |
| 悔棋 | 侧栏按钮 | `U`，焦点不在输入框时 |
| 重新开始 | 暂停层或侧栏按钮 | 确认后执行 |
| 返回 | 顶栏按钮 | `Esc` 打开暂停层后选择 |

### 4.5 悔棋规则

- 本地双人：每次悔棋撤销最后 1 手，最多 3 次；撤销后恢复该方回合。
- 人机：每次悔棋撤销最近的完整回合，即玩家的上一手与 AI 的回应；若 AI 尚未回应，则只撤销玩家一手。
- 结果产生后不可悔棋；可从结果页重新开始。
- 悔棋次数用 HUD / 侧栏显示，不得隐藏。
- 悔棋只影响当前局内存，不写历史结果。

### 4.6 AI 设计

AI 采用“启发式评估 + Alpha-Beta 搜索 + 时间预算”的混合方案，避免固定深度在高分支数下卡顿。

#### 候选点

- 首手落中心 `(8, 8)` 附近。
- 后续只考虑已有棋子周围 2 格内的空位。
- 对称等价点按固定顺序打破，保证调试可复现。
- 每一步先检查“立即获胜”和“必须封堵”的强制点。

#### 评估特征

| 棋形 | 分值级别 |
| --- | --- |
| 五连 | 胜利，最高优先级 |
| 活四 / 冲四 | 极高 |
| 双活三 / 活三 + 冲四 | 高 |
| 活三 | 中高 |
| 活二 / 眠二 | 低 |
| 中心控制与连通性 | 微调项 |

- 使用模式窗口扫描四个方向，统计连续、开放端与潜在延伸。
- 不允许 AI 在已有棋子的位置落子。
- 评估中加入防守权重，防止只进攻不封堵。

#### 难度档

| 难度 | 行为 | 时间预算 | 深度上限 |
| --- | --- | --- | --- |
| 入门 | 立即成五 / 堵五优先；简单启发式选点 | 200ms | 1–2 层 |
| 进阶 | 评估活三、冲四与双威胁 | 800ms | 2–4 层 |
| 大师 | 迭代加深、候选排序、Alpha-Beta 剪枝 | 2000ms | 4–6 层 |

- 超时立即返回当前最佳完整搜索结果，不阻塞 UI。
- AI 思考时显示“AI 思考中”，棋盘仍可查看但不可落子。
- AI 使用不可变局面快照，避免 UI 动画影响规则。
- 三档难度均不读取玩家存档或历史胜率，只使用当前棋盘。

### 4.7 计分与统计

五子棋不采用数字分数，以胜负和统计为核心：

| 数据 | 规则 |
| --- | --- |
| 对局结果 | 胜 / 负 / 平 |
| 总对局数 | 每局结束 +1 |
| 当前连胜 | 胜利 +1，失败/平局归零 |
| 最长连胜 | 只记录历史最大值 |
| 最快胜利 | 以步数和用时作为展示信息 |
| 总游玩时长 | 每局时长累加 |

结果页显示：胜者、总手数、本局用时、当前连胜、历史最长连胜和“再来一局/返回游戏库”。

### 4.8 开始、暂停与结束流程

1. 从游戏库进入 Ready 页面，选择“本地双人”或“人机对战”。
2. 人机模式选择难度；点击开始进入 Playing。
3. 黑棋先落；AI 模式下 AI 进入 Thinking 子状态，完成后落子。
4. 可随时暂停；暂停层冻结输入和 AI 搜索（如仍在思考则取消或丢弃结果）。
5. 五连出现时锁定棋盘、显示胜利线、展示 Result；平局同样锁定。
6. 重开清除上一局所有状态，不继承悔棋次数或 AI 搜索缓存。
7. 本地双人“再来一局”交换黑白；人机模式仍由玩家执黑。

### 4.9 界面布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 返回游戏库 | 星盘五子棋 | 对局中 | 音效 | 设置               │
├───────────────────────────────┬─────────────────────────────┤
│                               │ 对局模式：人机 · 进阶        │
│                               │ 当前回合：● 黑棋             │
│      15×15 星盘棋盘            │ 手数：24                    │
│      自适应正方形              │ 用时：03:12                 │
│                               │ 悔棋（2/3）  [重开]          │
│                               │ 最近一手 · 第 24 手          │
└───────────────────────────────┴─────────────────────────────┘
```

- 棋盘为优先级最高的区域，右侧面板宽约 280px。
- 棋盘线使用低对比度冰青，星位用暖金小点。
- 黑棋与白棋都用圆形棋子；黑棋实心、白棋空心，并用内高光区分，不只依赖颜色。
- 最近一手显示金色小环；胜利线用连续短线和半透明覆盖层强调。
- 坐标标签 A–O / 1–15 在棋盘边缘可关闭；默认开启以便复盘。
- AI 思考中显示顶部状态胶囊与低干扰进度点，不弹全屏加载层。
- 暂停/结果弹窗与合集通用规范一致。

### 4.10 存档与数据

- 首版只保存结果、统计、最长连胜与历史记录。
- 进行中的局面自动保存为 P1 扩展，需支持完整落子序列与 AI 难度恢复。
- 每局结束时生成唯一 `sessionId`，防止重复统计。
- 悔棋后不产生额外对局；重新开始视为放弃本局，不写入胜负。
- 历史记录保存模式、难度、结果、手数、时长和是否使用悔棋。

### 4.11 可访问性

- 棋盘支持方向键网格导航与 Enter 落子。
- 落子后通过 `aria-live` 播报：“黑棋落于 H8，轮白棋”。
- 胜利时播报胜者与胜利线方向。
- 当前焦点、最近一手、胜利线均使用形状或环线变化，不只使用颜色。
- AI 思考时间超过 1 秒时提供文本状态，避免无声等待。
- 色觉辅助模式可把黑棋与白棋显示为“实心 + 横纹 / 空心 + 点纹”。

### 4.12 扩展规划

- 人机对战中玩家可选择执白；
- 13×13 / 19×19 棋盘；
- 连珠禁手、Swap2 开局、五手两打；
- 在线房间对战（后续独立网络里程碑）；
- 对局回放、形势分析、AI 提示；
- 本地棋谱导出与导入；
- 观战模式与残局题。

### 4.13 验收标准

- [x] 横、纵、两条对角线五连与长连均正确判胜。
- [x] 非法落子不改变回合或棋盘状态。
- [x] 本地双人黑白交替、悔棋、重开正确。
- [x] AI 不会覆盖棋子，能完成立即五连并封堵对手立即五连。
- [x] 三档思考时间满足预算，超时后 UI 仍可操作。
- [x] 暂停时取消或丢弃仍在进行的 AI 搜索，不越过暂停落子。
- [x] 结果只统计一次，胜负、连胜、历史记录一致。
- [x] 键盘可完成模式选择、落子、暂停和再来一局。
- [x] 棋盘在 1040×700 窗口与 150% DPI 下完整可操作。

## 6. 内容与素材要求

- 三款游戏的视觉元素、角色、图标、音效与文案必须原创或具备可追溯授权。
- 不使用“马里奥”“Mario”作为游戏内名称、角色或宣传语；类型描述可以写“马里奥式横版平台跳跃”，但正式 UI 使用“冰原跃迁”。
- 所有可收集物、危险物、棋子和 UI 图形在色觉辅助模式下有非颜色差异。
- 关卡难度通过试玩数据进行调整；首版以“可完成、可理解、可重复挑战”为主。
- 每个游戏至少完成一次 30 分钟连续试玩，无崩溃、无存档丢失、无输入卡死。
