> 项目：Europa（木卫二） Windows 桌面端小游戏合集  
> 版本：v1.0.0 · M0 设计、M1 工程、M2 环带贪吃蛇、M3 冰原跃迁、M4 星盘五子棋、M5 设置/音频/记录、M6 稳定性/性能/可访问性与 M7 自动更新/打包发布

## 1. 产品定义

Europa 是太阳系软件系列中的 Windows 桌面小游戏合集，与 Mars、Ceres、Neptune、Titan、Miranda 保持统一的设计语法与本地优先原则。产品不依赖账号、不联网、不采集行为数据，打开即可游玩。

M0 完成以下设计交付：

1. Europa 极简 Logo 与完整矢量资产；

3. 开发流程、技术架构、里程碑、测试与风险文档；

## 2. 技术选型

### 2.1 总体方案

采用 **Tauri 2 + React 19 + TypeScript + Vite**。选择理由：

- 与 Mars、Titan 等系列项目的技术栈一致；
- Windows 安装包体积显著小于 Electron；
- WebView2 足以支撑 Canvas 2D、SVG 与高级玻璃 UI；
- Rust 侧集中处理窗口、SQLite 存档和系统能力，权限边界清晰；
- 前端游戏引擎可独立测试，不绑定桌面壳。

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 窗口、生命周期、打包、权限、IPC |
| UI | React 19 + TypeScript | 游戏库、游戏页面、设置和记录 |
| 构建 | Vite 8 | 开发服务器与前端产物 |
| 状态 | Zustand 5 | 主题、设置、应用导航、启动数据 |
| 图标 | 自绘 SVG 图标组件 | 统一线性 UI 图标并减少额外样式依赖 |
| 样式 | CSS Custom Properties + 组件 CSS | 延续系列 Token 体系，避免通用 UI 框架削弱品牌 |
| 平台跳跃 | Canvas 2D | 关卡渲染、角色和碰撞调试层 |
| 贪吃蛇 | Canvas 2D | 网格绘制、插值动画、特效层 |
| 五子棋 | SVG + DOM | 棋盘可访问性、落子命中、键盘导航 |
| 音频 | Web Audio API | 音效预加载、音量、暂停时静音 |
| 存储 | Rust + rusqlite（bundled） | 事务化本地数据与 schema migration |
| 打包 | Tauri NSIS | Windows x64 安装包 |
| 测试 | Vitest + Testing Library；Playwright 计划中 | 组件、引擎与后续浏览器级回归 |
| 质量 | ESLint + Prettier + TypeScript strict | 静态检查与格式统一 |

### 2.2 版本策略

- Node.js、Rust、Tauri CLI、WebView2 版本在仓库中固定并记录。
- `Cargo.lock` 与前端 lockfile 必须提交。
- WebView2 使用 Windows 10/11 自带 Evergreen Runtime；安装器检测失败时给出明确安装指引。
- 不引入远程脚本、CDN 字体、远程图片或运行时网络请求。

## 3. 系统架构

```text
┌─────────────────────────────────────────────────────────────┐
│                      React UI Shell                         │
│  GameLibrary / GameHost / Settings / Records / Overlays     │
├─────────────────────────────────────────────────────────────┤
│                    Application Services                     │
│  AppStore  |  SessionController  |  Audio  |  IPC Client    │
├─────────────────────────────────────────────────────────────┤
│                      Game Modules                           │
│  Platformer  |  Snake  |  Gomoku                            │
│  Engine（纯逻辑） + Renderer（Canvas/SVG） + Screen（React）   │
├─────────────────────────────────────────────────────────────┤
│                    Tauri IPC Boundary                       │
├─────────────────────────────────────────────────────────────┤
│                       Rust Core                             │
│  Window / Settings / SQLite / Migration / Diagnostics       │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 分层约束

1. **UI 只负责表达**：React 组件不直接写 SQLite、文件路径或窗口权限。
2. **游戏引擎与 React 解耦**：引擎接受固定步长与输入快照，输出状态和事件；可在 Node/Vitest 中单独运行。
3. **游戏之间不共享运行时状态**：共享的是壳层、音频、存储接口和设计 Token，而不是具体规则。
4. **全局 Store 不保存逐帧状态**：Zustand 只保留应用级数据；游戏内状态保存在 `GameSession`，避免每帧触发全局更新。
5. **Rust 是唯一持久化入口**：前端不直接使用通用文件系统 API，禁止从 IPC 传入任意磁盘路径。
6. **结果统一上报**：所有游戏通过同一 `GameResult` 契约上报分数、胜负、时长与元数据。

### 3.2 应用导航

```text
启动
  → 读取 Bootstrap（主题、设置、统计、最近存档）
  → 游戏库
      → 进入游戏
          → GameHost 初始化
          → 倒计时/开局
          → Playing
              ↔ Paused
          → Result
              → 再来一局 / 返回游戏库
      → 设置 / 游玩记录
```

不使用浏览器路由处理游戏内部状态；应用页面路由与游戏状态机分离。窗口缩放、失焦、暂停和返回都由 `GameHost` 负责。

### 4.2 合集框架模块

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `AppShell` | 窗口框架、导航、主题、启动状态 | 不包含游戏规则 |

| `SessionController` | 当前游戏会话、退出确认、存档协调 | 不保存逐帧对象 |
| `AudioService` | 预加载音效、音量、暂停时静音 | 首次用户交互后才启用 AudioContext |

| `AppStore` | 主题、设置、统计、最近游戏 | 只存可序列化应用数据 |
| `Persistence` | 设置、最高分、统计、检查点 | 事务化，失败有可见反馈 |

### 4.3 游戏模块统一接口

每个游戏至少导出以下四类能力：

```ts
type GameId = "platformer" | "snake" | "gomoku";

interface GameDefinition {
  id: GameId;
  meta: GameMeta;
  createSession(seed: number): GameSession;
  Screen: React.ComponentType<GameScreenProps>;
}

interface GameSession {
  start(): void;
  pause(): void;
  resume(): void;
  restart(): void;
  handleInput(input: GameInput): void;
  step(dtMs: number): void;
  getSnapshot(): RenderSnapshot;
  getResult(): GameResult | null;
  serialize?(): GameSave;
}
```

具体实现可为各游戏定制，但以下边界必须一致：

- 输入先归一化，再进入引擎；
- 引擎在暂停时不得推进；
- 结算只触发一次；
- 重开清空会话状态；
- 返回游戏库前停止 `requestAnimationFrame` 和音频；
- 结果必须包含 `gameId / outcome / score / durationMs / playedAt / detail`。

## 5. 数据与存档设计

### 5.1 存储位置

- 数据库：`{appDataDir}/Europa/europa.db`
- 日志：`{appDataDir}/Europa/logs/`
- 导出的诊断包：由 Rust 写入用户明确选择的位置，不在 MVP 中自动上传。
- 默认不开放任意路径读写能力。

### 5.2 SQLite 表结构

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE game_stats (
  game_id TEXT PRIMARY KEY,
  best_score INTEGER NOT NULL DEFAULT 0,
  games_played INTEGER NOT NULL DEFAULT 0,
  wins INTEGER NOT NULL DEFAULT 0,
  losses INTEGER NOT NULL DEFAULT 0,
  draws INTEGER NOT NULL DEFAULT 0,
  total_play_ms INTEGER NOT NULL DEFAULT 0,
  last_played_at INTEGER
);

CREATE TABLE platformer_saves (
  slot TEXT PRIMARY KEY,
  level_id INTEGER NOT NULL,
  checkpoint_id TEXT NOT NULL,
  score INTEGER NOT NULL,
  lives INTEGER NOT NULL,
  details_json TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE match_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  game_id TEXT NOT NULL,
  outcome TEXT NOT NULL,
  score INTEGER NOT NULL DEFAULT 0,
  duration_ms INTEGER NOT NULL,
  detail_json TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  session_id TEXT
);

CREATE UNIQUE INDEX IF NOT EXISTS match_history_session_id_unique
  ON match_history(session_id)
  WHERE session_id IS NOT NULL;
```

### 5.3 迁移策略

- 使用 `PRAGMA user_version` 管理 schema 版本。
- 每次启动先打开数据库、启用 WAL、检查版本，再执行顺序迁移。
- 迁移在事务内执行；失败则回滚并进入只读安全模式。
- 迁移前将旧数据库复制为 `europa.db.bak-v{version}`；当前 v1 → v2 迁移会生成 `europa.db.bak-v1`。
- 历史记录默认保留最近 500 局，可在游玩记录页手动清理。
- 写入最高分和统计使用同一事务，避免分数刷新但局数未增加。
- v2 为 `match_history.session_id` 建立唯一部分索引，环带贪吃蛇重复提交同一会话时返回现有统计且不重复计数。

### 5.4 各游戏存档粒度

| 游戏 | 保存内容 | 触发时机 |
| --- | --- | --- |
| 冰原跃迁 | 当前关卡、检查点、分数、生命、收集状态 | 到达检查点、完成关卡、暂停退出 |
| 环带贪吃蛇 | 仅最高分与统计数据 | 本局结束 |
| 星盘五子棋 | 最高连胜、胜负统计；进行中局面为 P1 扩展 | 每局结束 |

不允许在游戏运行中每帧同步写数据库；引擎快照先在内存中形成，再按明确触发点批量保存。

## 6. IPC 契约

### 6.1 原则

- 前端通过 `@tauri-apps/api/core` 的 `invoke` 调用 Rust 命令，但统一封装在 `services/ipc.ts`。
- 命令名、参数和返回值使用共享 TypeScript 类型；禁止在 UI 内出现 `invoke<any>`。
- 所有持久化参数在 Rust 侧再次校验，不能信任前端传入的分数、游戏 ID 或枚举值。
- 错误返回统一结构：

```ts
interface AppError {
  code:
    | "DB_UNAVAILABLE"
    | "MIGRATION_FAILED"
    | "INVALID_PAYLOAD"
    | "SAVE_CONFLICT"
    | "IO_ERROR"
    | "UNKNOWN";
  message: string;
  recoverable: boolean;
}
```

### 6.2 已接入与规划命令

| 命令 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `load_bootstrap` | 无 | `BootstrapData` | 设置、统计、最近存档、schema 状态 |
| `save_setting` | `key, valueJson` | `SettingValue` | 白名单 key，事务写入 |
| `submit_snake_match` | `SnakeMatchSubmission` | `SnakeMatchSubmissionResult` | M2 已接入；全字段校验、统计/历史事务写入、同一 `sessionId` 幂等 |
| `load_platformer_checkpoint` | `slot` | `PlatformerSave \| null` | M3 已接入；按槽位读取检查点存档 |
| `save_platformer_checkpoint` | `record` | `PlatformerSave` | M3 已接入；`platformer_saves` 按槽位 upsert |
| `clear_platformer_checkpoint` | `slot` | 无 | M3 已接入；删除指定槽位存档 |
| `submit_platformer_match` | `PlatformerMatchSubmission` | `PlatformerMatchSubmissionResult` | M3 已接入；全字段校验、统计/历史事务写入、同一 `sessionId` 幂等 |
| `submit_gomoku_match` | `GomokuMatchSubmission` | `GomokuMatchSubmissionResult` | M4 已接入；全字段校验、统计/历史事务写入、同一 `sessionId` 幂等 |

| `clear_platformer_saves` | 无 | `SavesClearResult` | M5 已接入；清空全部检查点存档（二次确认） |

### 6.3 事件

- `game://window-blur`：窗口失焦，由 Rust 发出，`GameHost` 自动暂停。
- `game://storage-warning`：数据库降级或写入失败，UI 显示持久提示。
- 游戏内高频状态不跨 IPC；渲染只在前端进行。
- 音频暂停策略：窗口失焦或 `document.hidden` 时挂起共享 AudioContext（`sharedAudio.suspend()`），恢复聚焦/可见后自动 `resume()`；三款游戏音效统一经 `sharedAudio` 播放，不重复创建实例。

## 7. 关键实现决策

### 7.1 游戏循环

- 平台跳跃：固定 60Hz 逻辑步长，`accumulator` 方式处理帧差异；渲染可插值。
- 贪吃蛇：逻辑 tick 独立于渲染帧；蛇身位置在 tick 之间线性插值。
- 五子棋：事件驱动，不使用动画帧循环推进规则。
- `document.hidden`、窗口失焦、暂停状态都会停止逻辑推进。
- 帧时间累计上限为 `100ms`，避免从后台恢复时出现“瞬间跳死”。

### 7.2 输入

- 统一监听 `keydown / keyup`，仅游戏舞台聚焦时接管游戏按键。
- 输入映射：方向键与 WASD 支持移动；Space、W、↑ 支持跳跃；Esc 暂停；R 重开需二次确认或在结果页启用。
- 防止系统键重复导致跳跃连发；维护按键状态和单帧 pressed 集合。
- 五子棋使用鼠标/触控点击及方向键 + Enter 落子。
- 音频与输入只在用户交互后启用，符合 Web Audio 自动播放策略。

### 7.3 渲染

- 平台跳跃：Canvas 2D，逻辑坐标 1280×720，按容器等比缩放；背景视差最多 3 层。
- 贪吃蛇：Canvas 2D，棋盘按可用空间正方形缩放；网格线与蛇身使用同一逻辑坐标系。
- 五子棋：SVG 棋盘 + DOM 控件，支持焦点管理与屏幕阅读器播报。
- Canvas 设置 `devicePixelRatio` 缩放并限制最高 `2×`，避免 4K 下过度绘制。
- 卡图采用内联 SVG 或独立 SVG 资产，不使用大尺寸位图作为主视觉。

### 7.4 音频

- 预加载短音效：按钮、收集、跳跃、碰撞、落子、胜利、失败。
- 单一 `AudioContext`；音量由设置控制，切换页面时 SUSPEND/RESUME。
- 暂停和失焦时立即静音；恢复时从原位置继续。
- 所有音频使用原创或明确授权的素材，仓库内保留来源清单。

### 7.5 安全

- Tauri 2 `capabilities/default.json` 只授予窗口最小能力，不启用 shell、任意 fs、http 或 opener 除非后续功能明确需要。
- 生产 CSP 禁止远程脚本与远程连接；不加载 CDN 字体或远程图片。
- SQLite 全部使用参数化查询；禁止拼接 SQL。
- 迁移、恢复与清除操作需二次确认或有备份。
- 关闭 DevTools 于正式安装包；开发配置与生产配置分离。
- 存档 JSON 设定最大长度与字段白名单，拒绝超范围和未知游戏 ID。

## 11. 代码质量与协作规范

- TypeScript 开启 `strict`、`noUncheckedIndexedAccess`、`noImplicitOverride`。
- 不使用 `any`；边界数据先校验再转换。
- 游戏引擎函数尽量保持纯函数；渲染与持久化副作用放在外层。
- 所有颜色来自 Token；禁止组件样式写死品牌色。
- 所有用户可见文案集中在本地化文件，不散落于 JSX。
- 提交前执行 typecheck、lint、unit tests、production build。
- PR/变更评审必须包含：规则影响、存档影响、可访问性影响、测试证据。
- Bug 修复先补复现测试；AI/碰撞缺陷必须留下固定棋局或输入序列。

## 12. 发布与运维

- 版本遵循 `0.x` 内测、`1.0` 正式版的语义版本策略。
- 正式版提供 NSIS x64 安装包与 SHA-256 校验值。
- 首版不启用自动更新；待稳定后再评估系列统一的 updater 流程。
- 崩溃日志本地留存，不上传；用户可手动导出诊断包。
- 发布说明列出新增、修复、已知问题与存档迁移说明。
- 回滚策略：保留上一版本安装包与数据库迁移备份，发布前在干净环境完成升级/回滚演练。
